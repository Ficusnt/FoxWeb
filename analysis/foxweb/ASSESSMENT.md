## Executive Summary

FoxWeb is a Cloudflare Pages + Workers Functions web application — a port of the Python Tkinter desktop app FoxReloaded. It fetches coefficient tables from agendae.com.ar, performs interest calculations on expense data, and generates PDF reports. The codebase is ~40 TS/TSX source files across `src/` (frontend + shared libs) and `functions/api/` (Workers Functions).

The system is small (~40 source files), well-structured with clean separation between UI (React components), business logic (src/lib/), and API routes (functions/api/). No test suite exists. No lockfile exists (package-lock.json was removed during cleanup). The build is currently broken: `react@^19.0.0` conflicts with `lucide-react@0.344.0` (requires react ^16-^18). This has been fixed in `package.json` (downgraded to `^18.3.1`) but not yet committed/pushed/verified.

**Recommended pattern:** Replatform (same stack, security-hardened build, fix bugs, remove dead code) — maps to `transform`. The code is small and clean enough that incremental hardening preserves all functionality while closing the findings.

## Business Flows

### Flow 1: Scrape tables from agendae.com.ar
1. User navigates to `/scraper` (or via `/wizard` step 1 → "Scraper" button)
2. Configures table entries (Nombre | URL) and retention (months)
3. Clicks "Ejecutar scraper ahora" → POST `/api/scraper/run`
4. Worker logs in via POST to `_login.aspx` with credentials from env vars
5. For each table: visits table page (sets Referer), POSTs to `_back.aspx` with `tipoEntidad=COEFICIENTES` + `idct`
6. Parses JSON response into coefficient matrix (month → year → value)
7. Saves CSV to KV namespace `TABLE_CSVS` under `FOLDER/NAME.csv`
8. Handles snapshot rotation: if month changed, moves current CSV to `NAME_YYYY-MM.csv`
9. Applies retention: prunes snapshots beyond configured count

### Flow 2: Enter data and generate PDF (Wizard)
1. User navigates to `/` (Wizard step 1)
2. Selects mode: TABLA or PORCENTAJE
3. Step 2: Enters Fecha MM/AA + Capital rows (or loads from PDF)
4. Step 3a (TABLA): Selects CSV table from scraped list, sets global multiplier
   Step 3b (PORCENTAJE): Sets base % and month shift
5. Step 4: Enters Administración / Edificio-Calle / Unidad
6. Clicks "Generar PDF" → POST `/api/pdf/generate`
7. Worker fetches CSV from KV (if tabla mode), runs calculation, generates PDF with pdf-lib
8. Streams PDF as HTTP response for download

## Recommended Modernization Pattern: Replatform

**Rationale:** The codebase is small (~40 source files), clean, and well-factored (separation of UI, business logic, API). It does not need a full rewrite or same-stack version uplift (already on current TypeScript/React/Vite). The right pattern is **replatform**: keep the same stack but harden it — fix the dependency conflict, add error handling, remove dead code, tighten security. The old desktop app (FoxReloaded) keeps running during the move (different deployment target anyway).

**Routes to:** `transform` — keep the same stack, fix issues incrementally.

**Does not apply:** Rehost (no value — same deployment target), Replace (no product to buy — custom business logic).
